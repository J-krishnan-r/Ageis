# Author's note

I chose a deterministic-first design because the project had to be completed with limited time and limited access to dependable AI resources. Model availability, API quota and cost, and the usable context window were practical constraints. I needed a system that could still run locally, cite exact passages, preserve revision-specific facts, and abstain when the supplied package did not establish an answer.

That constraint made explicit JSON facts, hand-reviewed source excerpts, and deterministic answer rules a reasonable first implementation. For questions the rules recognize, the behavior is visible and repeatable. The design also avoids asking a model to invent facts from an entire pile of mixed-format documents. But a rule table cannot anticipate every reasonable wording. As the assessment showed, a question can retrieve relevant material and still receive an incomplete answer, an unnecessary abstention, or an unsupported assumption. Adding a separate rule for every missed prompt would make the benchmark look better without making the system broadly more capable.

If I had more time and reliable AI capacity, I would prefer a fuller hybrid retrieval-augmented generation (RAG) architecture. I would keep deterministic checks for facts that should remain exact—firmware applicability, safety thresholds, interlocks, explicit source conflicts, and documented absence—but use retrieval and a language model for the long tail of natural-language questions. I would build it in these stages:

1. **Preserve the evidence layer.** Continue extracting source text with page, section, cell, slide, or image-region locators. Keep reviewed visual transcriptions distinct from parser output. Retain document revision, source type, confidence, and scope metadata so that later components can reason about which evidence applies.
2. **Retrieve with complementary signals.** Use lexical retrieval such as BM25/FTS for exact tags, alarm codes, and version strings, alongside embedding-based retrieval for paraphrases and conceptual matches. Apply metadata filters for firmware, component, document status, and source scope. Merge and deduplicate the candidate lists instead of trusting one retrieval score.
3. **Rerank evidence for the question.** Score candidate passages for direct answer coverage, source authority, scope, and version applicability. Prefer a short set of passages that jointly support the answer over a large set of merely related chunks. Expand or join neighboring chunks when tables, warnings, or a sequence span multiple segments.
4. **Assemble a bounded evidence packet.** Send the question and the best source excerpts to the model, with stable citation IDs and enough surrounding text to preserve qualifiers. Include relevant curated claims where useful, but keep the original passages available so the model can be checked against them. Mark low-trust observations and conflicting sources explicitly.
5. **Generate with claim-level grounding.** Require structured output in which each material statement points to one or more supplied evidence IDs. The model should distinguish what a source states from what it does not establish, preserve uncertainty and revision scope, and abstain when the retrieved evidence is weak or contradictory. Validate IDs in code, then add a second support check (for example, an entailment or evidence-coverage pass) rather than treating a valid citation ID as proof that the quote entails the claim.
6. **Apply deterministic safety and scope checks.** Before returning an answer, verify critical constraints such as “below 50 bar” versus “above 50 bar,” active-sensor-by-firmware mappings, and restrictions attached to a specific document or machine. These checks should be general domain invariants, not one-off rules written to match evaluation questions. A failed check should cause a correction or a clear abstention.
7. **Evaluate without tuning to the test set.** Maintain separate development and held-out question sets. Include exact questions, paraphrases, multi-part questions, low-trust notes, conflicting evidence, and unanswerable premises. Measure answer correctness, completeness, citation precision and recall, abstention quality, unsupported-claim rate, latency, and cost. Keep final assessment questions out of the rule-writing loop.

This would be a hybrid system in a meaningful sense: deterministic logic would protect narrow, high-consequence invariants; hybrid lexical and semantic retrieval would locate evidence; and generation would explain that evidence in natural language. It would still need careful testing. RAG reduces the amount of irrelevant material sent to a model, but it does not guarantee that retrieval finds every relevant passage or that the model interprets the selected passages correctly.

The current application is an incremental step toward that design: it combines deterministic rules with SQLite full-text retrieval and an optional LiteLLM/Groq evidence-grounded generation path. Its search is lexical rather than dense-vector hybrid retrieval, and its citation validation checks that returned IDs exist, not that every generated statement is fully entailed by its cited passages. The latest independent 20-question assessment is recorded in `reports/INDEPENDENT_DATASET_20Q_ASSESSMENT.md`; its results should be treated as diagnostic evidence of remaining gaps, not as proof that the architecture is complete.
